**Seventh pass: index bitmap lifetimes, cache hits and selective intersections — 11 September 2026**

Follow-up: the [eighth pass](insert_pass8_20260911.md) accelerates large floating-point overwrite batches, repairs statistics after deletion, and fixes byte-aligned timestamp packing. It retains an unresolved short-series regression.

This pass reduces CPU work and allocation churn in index lookups and existing-series day membership. Cached tag cardinality is **2.66–2.73× faster** in the focused benchmark, time-filtered discovery is **1.51–2.68× faster**, and existing day-membership updates are **1.12× faster**. HTTP results are mixed; these ratios are not whole-server speedups. The overall optimization goal remains active.

The baseline is the sixth-pass worktree, including its provisional WAL timestamp reuse. Both binaries therefore include that WAL optimization. An independently reviewable [production patch](query_pass7_20260911/production.patch) contains only this pass's native-index changes.

**Changes and lifetime invariants**

Previously, private bitmap loaders returned pointers into `robin_map` through futures. Seastar's coroutine awaiter can yield even when a future is ready: `await_ready()` checks both availability and `need_preempt()`. Thus a loader could finish, another task could rehash/evict the cache, and the caller could resume with a dangling pointer. Copying the bitmap immediately after `co_await` does not close that gap.

The loaders now consume synchronous visitors before completing their futures. Read visitors copy or intersect into caller-owned results; write visitors update the cache before returning. No borrowed bitmap pointer or iterator escapes through the future. Visitors must not suspend, mutate the bitmap cache's structure, or retain pointers. Cold paths still re-find entries after storage reads and merge persisted bitmaps with concurrent additions. HLL seeding also consumes the bitmap through this interface and re-finds the sketch after loading.

Hot paths return ready futures without allocating coroutine frames. Only cold/loading paths enter coroutines. Exceptions from synchronous visitors become failed futures. This retains normal error propagation while reducing allocation churn. An initial visitor implementation allocated a coroutine on every hit and regressed the ordinary multi-tag control by 9.3%; splitting the hot path reduced that regression to 0.9% in the final comparison, with two fewer allocations per operation. [Initial measurements](query_pass7_20260911/results/initial-cpu/summary.json) are retained separately.

Two query optimizations accompany the lifetime change:

- A complete cached bitmap below the existing 10,000-series HLL threshold supplies exact tag cardinality immediately. It avoids repeated absent-sketch KV reads, duplicate key construction and bitmap reload calls. Missing/loading entries and larger sets retain the fallback paths. This API serves `/cardinality`; it is not a new query-planner optimization.
- Time-scoped discovery intersects filters directly into the owned time-window bitmap. It avoids copying a potentially larger tag bitmap and exits as soon as the active set becomes empty. Limits are applied to the final intersection, as before.

No persistent cache or per-entry field is added. Fewer allocation calls establish reduced churn, not a measured reduction in peak resident bytes. Cold coroutine frames now also own their visitors; this pass does not establish minimum possible frame size.

**Focused CPU and allocation measurements**

Both versions use the same driver, GCC 14 release flags, one Seastar shard on CPU 4, 4 GiB, and fresh tmpfs directories on the same Ryzen 9 7950X. Three alternating pairs run after/before, before/after, after/before. Each process performs one warmup and six measured repetitions per case. Values are medians of the three process medians. Setup, index sync and close are outside timing. There are no concurrent builds or test runs during measurements.

The fixture has 8,192 hosts, one field each, two cohort values and four regions. Only 32 hosts occupy the queried day; other hosts occupy the next day. Cardinality and existing-membership cases perform 100,000 operations per repetition; discovery cases perform 1,000. Timing includes filter/key preparation, result destruction and correctness assertions, identically in both versions. Allocation counts are shard-local `seastar::memory::stats().mallocs()` deltas, including those driver operations and any reactor work during yields. Fractional counts reflect varying string lengths across hosts.

**HTTP measurements and limits**

Servers use four shards on CPUs 0–3, 8 GiB, fresh tmpfs data directories and default `always` WAL durability. The query probe pins its Python client to CPU 6 after spawning the server. It loads the same 8,192-host pattern, performs 2,400 requests per shape/run using 80 sequential connections, and excludes each connection's first five requests: 2,000 timed requests per shape/run. Request preparation, parsing and exact value/cardinality checks are outside timing. Every response is checked. Three alternating pairs yield these medians of process medians:

| HTTP operation | Before, ms | After, ms | Latency change |
|---|---:|---:|---:|
| Host cardinality | 0.0643 | 0.0685 | 6.6% higher |
| Region cardinality | 0.0670 | 0.0669 | Essentially unchanged |
| Time + tags, positive cached discovery | 0.1383 | 0.1360 | 1.6% lower |
| Time + tags, empty uncached discovery | 0.0878 | 0.0786 | 10.5% lower |
| Single-tag cached control | 0.0813 | 0.0861 | 5.8% higher |

These small request times vary materially between processes. The empty-query case benefits where discovery is repeated; positive discovery is cached. Host-cardinality and single-tag controls regressed in the aggregate, and their run ranges overlap. An earlier shorter unpinned comparison was also mixed. Neither comparison establishes a general HTTP latency gain. [Final HTTP data](query_pass7_20260911/results/query-http/summary.json) and [initial data](query_pass7_20260911/results/initial-query-http/summary.json) retain the differences.

The unchanged native insert benchmark also ran three alternating pairs per format: 200 timed batches × 10,000 timestamps × ten fields, eight connections and ten warmup batches. Each field was subsequently checked with a separate COUNT query; all twelve runs acknowledged every timed request and returned exactly 2,100,000 points per field, including warmups.

| Durable-ack HTTP insert on tmpfs | Before, million points/s | After, million points/s | Change |
|---|---:|---:|---:|
| JSON | 110.24 | 114.17 | +3.6% |
| Protobuf | 78.22 | 77.02 | −1.5% |

Run ranges overlap, so throughput gains remain inconclusive. Tmpfs excludes physical disk persistence costs. [Insert measurements and per-field verification](query_pass7_20260911/results/insert-http/summary.json) are retained.

**Validation and the earlier crash**

The release full suite passed 3,920 tests, with ten existing skips. After adding the threshold test, a four-shard index/bitmap/cardinality/HLL selection passed 80 tests. New tests exercise cache rehash/eviction between future completion and caller resumption, and exact cached/cold/reopened cardinality after an additional insert. A source-inspection assertion was updated for the visitor-based HLL lookup. The initial cold-reload test incorrectly assumed `sync()` flushed tag postings; it now closes and reopens the index before evicting the bitmap.

The added threshold test creates 10,000 series sharing a region tag, confirms no sketch exists below the threshold, then checks that the first sketch includes the earlier IDs. It also checks a subsequent insert after close/reopen and bitmap eviction. All 80 selected tests passed; the full-suite result above predates this test addition.

Four current-server runs under AddressSanitizer and UndefinedBehaviorSanitizer completed all 200 timed protobuf writes and all per-field COUNT checks without reported invalid access or undefined behavior. Leak detection was disabled; diagnostic timings are not performance evidence. Sanitized runs emitted reactor-stall warnings. [Diagnostic logs](query_pass7_20260911/results/sanitized/results.json) and release validation logs are retained.

The bitmap completion/resumption gap is a concrete lifetime hazard, and this implementation removes it. **It has not been established as the cause of the earlier allocator crash.** That crash was not reproduced here. The [sixth-pass report](insert_pass6_20260911.md) remains provisional; successful stress runs must not be treated as proof that its crash is fixed.

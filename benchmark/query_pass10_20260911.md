**Tenth pass: direct packed-timestamp reads and defined delta arithmetic — 11 September 2026**

The timestamp decoder now reads packed words directly from byte-aligned input, removing an **8 KiB alignment buffer and its copy** from each nonconstant block decode. Full irregular-timestamp decoding improves approximately **3–7%** in the final seven-pair comparison. Regular filtered decoding is approximately **4% slower**, and HTTP results are mixed. The change also fixes reproduced signed overflow in timestamp delta arithmetic. These are specific improvements with recorded tradeoffs; the overall compute/memory optimization goal remains active.

The baseline is the completed ninth-pass worktree. [The production patch](query_pass10_20260911/production.patch) isolates this pass's encoder/header changes. Matching baseline sources, library and server are preserved under ignored `build/perf-query-pass10-before`.

**Direct reads and stack usage**

`ffor_unpack_u64` and its unsigned power-of-two helper now accept a byte-aligned input pointer. Each packed word is loaded with fixed-size `memcpy`, which permits native word loads without imposing uint64 alignment on WAL/TSM byte storage. Bit order, word layout, output count, unsigned base arithmetic, special bit widths and corruption checks remain unchanged. Signed unpacking is unchanged.

`decodeBlockInto` passes the original packed bytes to a separate unpack helper. The existing decoded-value block buffer remains: this pass removes the alignment staging buffer, not all block scratch space. No persistent field, heap buffer or allocation is added.

On the measured GCC 14 build, the block helper's explicit stack reservation falls from **8,512 bytes to 256 bytes**. The unpack wrapper tail-calls the unpack function; the latter saves registers but has no large array reservation. The outer decoder retains its 8 KiB decoded-value buffer. These are disassembly and source-level stack measurements, not peak RSS estimates. [Before assembly](query_pass10_20260911/results/before-decode-block.asm), [final block helper](query_pass10_20260911/results/final-decodeBlockInto.asm) and [unpack assembly](query_pass10_20260911/results/final-ffor_unpack_u64.asm) are retained.

Simply removing the copy was insufficient. The first integrated candidate was 13–32% slower on irregular input even though the standalone unpack loop improved slightly. Its larger block function spilled loop state inside the generic unpack loop. An aliasing annotation did not improve the result and was removed. Separating unpacking from header/exception handling removed that regression. The rejected measurements and source snapshot remain under `results/initial-*`; the exploratory aliasing and outlined measurements are also retained.

**Arithmetic correctness and compatibility**

The broader sanitizer selection stopped on an existing `IntegerEncoderOverflow.LargeDeltas` fixture: the scalar encoder tail subtracts signed values across the int64 boundary. A standalone UBSan reproducer compiled directly from the preserved baseline expression fails with the same signed overflow. [Baseline reproduction](query_pass10_20260911/results/baseline-overflow.log) and [source](query_pass10_20260911/overflow_probe.cpp) establish that this arithmetic predates the copy-removal change.

The encoder now subtracts unsigned timestamp values modulo 2^64 and bit-casts the resulting delta bits for ZigZag encoding. Both filtered and full decoders accumulate unsigned delta bits and timestamps with the same defined modular arithmetic. This matches the existing SIMD lane arithmetic across the complete uint64 domain, including backwards steps and values crossing 2^63. It does not add checks or allocations to the per-point loop.

Regression tests cover full-domain extremes across scalar tails and 1,024-point block boundaries, plus a sorted filtered stream crossing the signed boundary. A separate compatibility driver exercises thirty random, extreme and ordinary timestamp streams of lengths 1–65,537. Both preserved release baseline and candidate roundtrip every stream; their concatenated encoded bytes compare **exactly equal**. [Artifact hashes](query_pass10_20260911/results/artifacts.json) include both wire fixtures. This is tested compatibility for those fixtures, supported by unchanged packing/layout logic.

Independent bit-level tests construct reference packed words without using the production packer. They cover widths 0–64, eight byte offsets, empty/partial/full blocks, unsigned base wraparound and exact allocation ends. Output guards catch extra writes; sanitizer allocation boundaries catch trailing reads. Timestamp tests verify filters across a block boundary and append-to-existing-output behavior at every byte offset. Existing ALP tests cover the other unsigned-unpacker caller.

**Codec measurements**

The driver measures the actual `IntegerEncoderFFOR::decode` API. Inputs contain 1,024 or 65,537 points: regular spacing, spacing jitter limited to 8/20/32 bits, or occasional large exceptions. It tests input offsets zero and three, full decode, a middle-third time filter and an early cutoff after 128 points. Input generation, encoding and final value comparisons are outside timing; returned counts are checked in the timed loop. Output capacity is reserved and reused equally in both versions. Each case has one warmup and six measured repetitions, with at least 32 calls and roughly two million processed input points per repetition (the early-exit fixture uses a 1,024-point work estimate).

Final codec conclusions use **seven alternating process pairs on CPU 12** of the Ryzen 9 7950X, GCC 14 release flags. The table gives medians of process times and the median of paired speedups. Compilation, tests and other project benchmarks do not overlap timing.

A prior CPU 4 rerun exhibited abrupt approximately 1.8× timing shifts affecting both binaries; aggregating those samples yielded contradictory apparent gains and losses. A read-only CPU activity sample found CPU 12 and its sibling idle, so the full comparison was repeated there with more pairs. No unrelated process or host setting was changed. The anomalous run is retained under `results/cpu-noisy`; it is not used to claim a speedup. The final per-pair results are consistent for the main irregular workloads.

**Validation and reproduction**

The final release suite passes **3,934 tests**, with ten existing skips. The final ASan/UBSan correctness selection passes **135 tests**, and the sanitizer server completes the TSM flush/restart/query workload with all results verified. Leak detection is disabled; the sanitizer build uses the default allocator and ignores `--memory`. ASan emits its usual warning about incomplete `makecontext`/`swapcontext` support.

The first sanitizer run stopped on the inherited signed overflow and encountered a nested ASan failure while reporting it. After the arithmetic fix, an accidentally included release performance ceiling failed under instrumentation: single-point encoding measured 80.947 µs against a 5 µs ceiling. That timing test remains enabled and passing in the full release suite. It was excluded from the final sanitizer correctness selection; no threshold was relaxed.

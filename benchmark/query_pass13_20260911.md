**Thirteenth pass: decode selected integer values without full-block scratch — 11 September 2026**

Integer TSM reads now decode signed values directly into the result or the aggregator's double buffer. Full-block unsigned scratch is removed. Direct TSM decoding is **1.5× faster for full blocks** and **up to 2.9× faster for late ranges** in the measured workloads. End-to-end integer bucketed AVG latency falls **12–17%**, and middle-range SUM falls **9%**. Timestamp-only controls are approximately unchanged.

The baseline is the completed [twelfth pass](query_pass12_20260911.md). Preserved baseline sources, server and static library are under ignored `build/perf-query-pass13-before`. The [production patch](query_pass13_20260911/production.patch) isolates the new encoder API and TSM call-site changes. [Measured artifact hashes](query_pass13_20260911/results/artifacts.json) identify the benchmark builds. A final formatting cleanup and merge validation are recorded separately below.

**Implementation and correctness bounds**

Two `decodeSigned` overloads append signed integers or their double conversions for an index range. They clamp skip/length without overflowing their sum. Prefix values establish delta state without entering an intermediate heap vector. Returned values reconstruct in the existing 1,024-entry stack buffer and convert in a separate loop, allowing vectorized ZigZag and int64-to-double conversion. Constant-delta groups generate converted progressions directly.

For at least sixteen skipped deltas, the decoder computes the final state with unsigned reductions. For skipped deltas `d[0..k)`, it adds `sum(d)` to the old delta and adds `k * old_delta + sum((k-i) * d[i])` to the old value. All arithmetic is modulo 2^64, preserving negative deltas and wraparound. Short prefixes use the scalar recurrence. GCC 14 emits vector additions and multiplications for this helper; [assembly](query_pass13_20260911/results/skipIntegerDeltas.asm) is retained.

Trailing groups still receive the existing header, packed-payload, exception-position and exception-value bounds checks, through the caller's requested count. A compile-time validation-only specialization avoids unpacking or reconstructing unselected suffixes. It still consumes whole groups and rejects malformed suffixes. Direct and single-block TSM reads retain their full declared-count validation; aggregation retains its existing prefix-count bound. Timestamp decoding continues to use the materializing specialization.

The new path replaces unsigned scratch in synchronous block reads, asynchronous single-block reads, batched flat reads, and integer aggregation. Appended output grows geometrically when necessary. No storage encoding changes are made. The existing timestamp API is unchanged; signed-range overloads are added to the encoder API.

Range tests use an independent signed-value oracle across constant, positive/negative ramp, alternating INT64 extrema, random full-width and sparse-extreme data. They cover eight byte offsets, empty/short/truncated requested counts, prefix preservation, group boundaries, 15/16/17-point skip boundaries, overflowing skip/length arguments and double conversion. Additional raw-header fixtures cover empty and single-value groups and malformed unselected suffixes. Cursor positions are compared with the existing full decoder.

The final semantic implementation passes **3,947 release tests**, with ten existing skips, and **109 focused ASan/UBSan correctness tests** on four shards. The sanitizer server loads four 65,536-point float/integer series, flushes, restarts, and verifies **3,200 query responses**. Thirty compatibility streams roundtrip and encode identically in both builds. Leak detection is disabled, the sanitizer uses the default allocator, and its existing makecontext/swapcontext instrumentation warning applies. [Validation details](query_pass13_20260911/results/validation.txt) retain the commands and logs.

**Memory**

The removed unsigned scratch reserves **24,000 bytes for 3,000 values** or **524,288 bytes for 65,536 values** in the baseline signed driver. The candidate has no such heap vector. It retains the existing 8 KiB group scratch on the stack and the actual result buffer. TSM timestamp/value result capacities match the twelfth-pass baseline; this pass removes intermediate storage rather than shrinking results further. Reused aggregation output still retains its capacity, and geometric growth can retain spare capacity during batched output.

Median whole-process peak RSS is **13,272 → 12,784 KiB** for the signed driver, **19,956 → 19,772 KiB** for direct TSM decoding, and **13,256 → 13,332 KiB** for timestamp controls. These include fixtures, runtime state and all cases. Each result directory contains all samples and capacity measurements in `memory.json`.

The HTTP driver also reads each server's `/proc/PID/status` before shutdown, after all requests. Median query-process RSS high-water marks are **75,204 → 74,536 KiB**; current RSS equals the high-water mark in these samples. This small difference lies within the overlapping run ranges and does not establish a general server peak-memory reduction. Load-process high-water marks are **86,496 → 86,100 KiB**, sampled before graceful flush/shutdown. No sustained-compaction or shutdown peak-memory claim is made. [HTTP memory samples](query_pass13_20260911/results/http/memory.json) retain all seven pairs.
